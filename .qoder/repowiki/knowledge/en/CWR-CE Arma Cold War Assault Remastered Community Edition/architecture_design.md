The repository is split into two parallel build systems that share the same source tree: CMake (root `CMakeLists.txt`) builds the C++ engine (`engine/Poseidon`, `PoseidonGL33`, `PoseidonOpenAL`, `PoseidonFormats`) and application targets (`apps/cwr/Game`, `GameDemo`, `Server`, `tools/*`), while Cargo (root `Cargo.toml`) manages the Rust workspace containing the Trident test runner, the wgpu renderer cdylib, and the mserver crates. The CMake top-level script wires everything together via `add_subdirectory` calls in a fixed order, generates `BuildConfig.h`, registers Catch2 unit tests and Trident integration tests, and applies a shared precompiled header (`PoseidonPCH.hpp`) across all substantial targets. Cross-language linkage happens through the wgpu backend: the Rust `cdylib` is fetched via CMake FetchContent and linked into the game through a hand-written C ABI (`include/wgpu_renderer.h`). vcpkg supplies C++ dependencies (glad, RenderDoc, etc.) declared in `vcpkg.json`, while third-party vendored headers live under `thirdparty/`. Build presets in `CMakePresets.json` plus toolchain files in `cmake/toolchains/` target Windows x64 and Linux x64 with Clang, producing binaries staged into `dist/<preset>/`. A single `.trident.env` config ties the Rust `tri` CLI to both built binaries and external game data.
