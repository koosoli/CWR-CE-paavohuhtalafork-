- Each platform/arch combination gets a paired vcpkg triplet (under `vcpkg-triplets/`) that sets `VCPKG_TARGET_ARCHITECTURE`, `VCPKG_LIBRARY_LINKAGE`, and chains to a corresponding toolchain file under `toolchains/` via `VCPKG_CHAINLOAD_TOOLCHAIN_FILE`.
- CMake presets follow a layered inheritance pattern: `base.json` holds shared settings (Ninja, vcpkg paths, ccache), while `linux.json` and `windows.json` define hidden build-type presets that inherit base and expose public presets with explicit `binaryDir` and `VCPKG_TARGET_TRIPLET`.
- Toolchain files are minimal and declarative: they only set compiler names, cross-compilation flags (`-m64`, `/machine:x64`), and include `FindLLVMSanitizer.cmake` to resolve LLVM tool paths rather than hardcoding paths.
- vcpkg overlay ports use `vcpkg_from_github` with an explicit SHA512 and list all patches under the port directory, then drive feature selection through `vcpkg_check_features` and per-target `VCPKG_TARGET_IS_*` macros.
- Build metadata is generated at configure time by `GenerateBuildInfo.cmake`, reading `OFPR_BUILD_VERSION_TAG` from the environment and writing a C++ header into `Poseidon::BuildInfo` with git SHA, effective tag, and release flag.
